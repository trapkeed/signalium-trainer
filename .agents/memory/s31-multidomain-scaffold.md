---
name: S31 multi-domain scaffold (SSO nonce, RunPod, market data, sync)
description: Where the 5-domain infra spec landed and the stub-until-configured pattern used for external providers
---

Implemented four new domains as pure-Python scaffolding, no live network calls:

- **SSO nonce replay protection**: added to existing `trainer/research_lab/sso.py` (not a new file) — `NonceStore` class (`ttl_s` param, `consume(nonce, now=None) -> bool`, no exception from the store itself), `ReplayedNonce` exception raised only by `validate_signalium_jwt(..., nonce_store=, require_nonce=)`. Distinct from the pre-existing jti-based dedup in `session_manager.py` (session-establishment layer) — this is token-validation-layer, so any caller of SSO validation gets replay protection, not just session creation.

- **RunPod execution model**: new `trainer/infra/` package (not `trainer/execution/`, which is trade execution — order strategy/position sizing, unrelated). `RunPodCredentials` (frozen dataclass with `assert_usable(shared_secret, now=)` — checks expiration AND HMAC signature, fails closed on either) + `ExecutionBackend` protocol with `LocalWorkerBackend` (sync in-process) and `RunPodWorkerBackend` (validates credentials before every `submit()`/`health_check()`, delegates actual network call to an injectable `dispatch_fn` so the class has zero HTTP dependency). `select_backend(name, ...)` factory is the single call site the training engine should import.

- **Pluggable market data providers**: new `trainer/market_data/` package. `MarketDataProvider` Protocol (connect/disconnect/health_check/get_price/get_candles/get_ticks/get_spread/get_orderbook/get_calendar/get_news). `OandaProvider`/`TiingoProvider` both subclass `BaseStubProvider`, which raises `ProviderNotConfigured` from every data method until an API key is present (env var or injected) — same stub pattern for both, so graduating either to live only requires implementing its `_request` seam. `ProviderManager` holds independent priority lists per `DataContext` (LIVE=[OANDA,Tiingo], TRAINING=[Tiingo,OANDA]), fails over on error/timeout/excessive-latency/stale-data (via optional `staleness_extractor`), tracks per-provider degradation with a cooldown window.

- **Universal symbol normalization**: `trainer/market_data/symbol_normalizer.py`, separate from `trainer/validation/instrument.py` (unrelated canonical registry) and `trainer/research/normalization.py` (math normalization, unrelated). Resolution order: exact → admin alias → builtin alias → learned (runtime) alias → structural stripping (separators, dot-suffixes, trailing broker-type letter). **Gotcha**: the trailing-letter regex must be case-insensitive even though input is pre-uppercased for matching — `re.compile(r"(m|c|i)$")` without `re.IGNORECASE` silently fails to strip `EURUSDM` because the class was written lowercase; always add `re.IGNORECASE` on any regex applied after `.upper()`.

- **Sync/reconciliation**: `trainer/sync/reconciler.py`. `SyncReconciler` per-domain via `DomainHandler(fetch_remote, apply_local)`; idempotency is at the reconciliation-record level (`(domain, record_id) -> last_applied_version`), distinct from and layered on top of any DB-level `INSERT OR IGNORE` idempotency inside `apply_local` itself. Persistent `apply_local` failures after `max_retries` go to an in-memory DLQ (`dead_letters()`), operator can `requeue_dead_letter()` to force a re-attempt on the next `run_once()`. Every attempt (applied/skipped_idempotent/retrying/dead_lettered) is captured in `audit_log()`.

**Why stub pattern**: user explicitly chose "build everything now, real API calls later" — every external-dependency seam (`OandaProvider._request`, `TiingoProvider._request`, `RunPodWorkerBackend`'s `dispatch_fn`) is isolated to one method/parameter so swapping in real credentials/HTTP later touches only that one seam, not `ProviderManager`/`SyncReconciler`/the training engine.
